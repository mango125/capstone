# 컴퓨터 부품 쇼핑몰

2023년 대학교 캡스톤 디자인으로 진행한 컴퓨터 부품 쇼핑몰 프로젝트입니다.

완성된 쇼핑몰 서비스를 만드는 것뿐만 아니라, CPU·메인보드·그래픽카드처럼 서로 다른 속성을 가진 컴퓨터 부품을 관계형 데이터베이스로 어떻게 표현할지 설계하는 데 중점을 두었습니다.

> 이 프로젝트는 데이터베이스 설계와 일부 백엔드 기능을 구현한 프로토타입입니다.  
> 전체 기능과 프론트엔드 구현은 완료되지 않았습니다.

## 1. 프로젝트 개요

컴퓨터 부품은 상품마다 공통으로 필요한 정보가 있지만, 부품 종류에 따라 필요한 상세 정보가 크게 다릅니다.

예를 들어 모든 상품에는 상품명, 가격, 제조사와 같은 공통 정보가 필요하지만 다음과 같은 정보는 특정 부품에만 필요합니다.

- CPU: 소켓, 코어, 스레드, 클럭
- 메인보드: CPU 소켓, 칩셋, 폼팩터, 메모리 슬롯
- 그래픽카드: GPU 칩셋, 인터페이스
- SSD: 용량, 인터페이스, 폼팩터
- 케이스: 지원 메인보드 규격과 크기

이러한 차이를 하나의 상품 테이블에 모두 저장하지 않고, 공통 정보와 부품별 상세 정보를 분리하는 방향으로 데이터베이스를 설계했습니다.

부품별 규격과 호환 관계를 데이터로 표현하여, 사용자가 전문 지식 없이도 부품 간 호환 여부를 판단할 수 있는 구조를 설계했습니다.

## 2. 사용 기술

- C#

- Entity Framework Core 7

### Database

- Microsoft SQL Server

## 3. ERD

총 29개 테이블을 설계했습니다.

주요 영역은 다음과 같습니다.

- 사용자 및 배송지

- 부품 종류별 상세 정보
- 제조사 및 부품 규격
- 주문 및 주문 상세
- 상품 후기
- 사용자 문의

## 4. 주요 데이터베이스 설계

### 4.1 공통 상품 정보와 상세 정보 분리

`product_info` 테이블에는 모든 상품에서 공통으로 사용하는 정보를 저장하도록 설계했습니다.

- 상품 번호
- 상품 분류
- 상품명
- 제조사
- 가격
- 판매 상태
- 품절 상태
- 이미지
- 상품 설명

부품별 상세 정보는 별도의 테이블로 분리했습니다.

- `product_CPU`
- `product_mainboard`
- `product_VGA`
- `product_ram`
- `product_SSD`
- `product_HDD`
- `product_case`

각 상세 테이블의 `productNum`은 상품 공통 정보와 연결됩니다.

이 구조를 통해 특정 부품에서만 사용하는 컬럼 때문에 다수의 `NULL` 값이 발생하는 것을 줄이고, 부품 종류별 속성을 독립적으로 관리하고자 했습니다.

### 4.2 부품 규격의 참조 테이블 분리

반복해서 사용되는 부품 규격은 별도의 참조 테이블로 분리했습니다.

- 제조사
- CPU 소켓
- CPU 칩셋
- 메인보드 칩셋
- 메인보드 폼팩터
- RAM 소켓
- VGA 칩셋
- VGA 인터페이스
- M.2 인터페이스
- SSD 폼팩터
- 케이스 크기

문자열을 상품마다 반복해서 저장하는 대신 식별자를 통해 참조하도록 설계했습니다.

### 4.3 다대다 관계 표현

하나의 메인보드는 여러 인터페이스를 지원할 수 있고, 같은 인터페이스도 여러 메인보드에서 사용될 수 있습니다.

이를 표현하기 위해 다음 연결 테이블을 구성했습니다.

- `mainboard_VGAInterface`
- `mainboard_M.2Interface`

연결 테이블에서는 두 외래키를 조합한 복합키를 사용해 동일한 관계가 중복으로 저장되지 않도록 설계했습니다.

### 4.4 주문 정보 분리

주문 자체에 대한 정보와 주문에 포함된 상품 목록을 분리했습니다.

- `order`: 주문자, 결제 및 배송 상태 등 주문 공통 정보
- `order_detail`: 주문에 포함된 상품과 수량

한 번의 주문에 여러 상품이 포함될 수 있도록 일대다 관계로 구성했습니다.

### 4.5 사용자 관련 데이터 분리

사용자 정보와 함께 다음 데이터를 독립된 테이블로 관리하도록 설계했습니다.

- 배송지
- 상품 후기
- 문의
- 주문 내역

사용자가 여러 배송지를 저장하거나 여러 후기와 문의를 작성할 수 있는 관계를 표현했습니다.

## 5. 프로젝트를 통해 배운 점

컴퓨터 부품처럼 종류마다 서로 다른 속성을 가진 데이터를 하나의 테이블에 모두 저장하면 구조가 복잡해지고 불필요한 `NULL` 컬럼이 증가할 수 있다는 점을 확인했습니다.

이를 해결하기 위해 공통 상품 정보와 부품별 상세 정보를 분리하고, 반복되는 규격은 참조 테이블로 구성했습니다.

또한 ERD 설계만으로 프로젝트가 완성되는 것은 아니며 다음 작업이 함께 필요하다는 점을 배웠습니다.

- 데이터베이스 제약조건 정의
- 애플리케이션 모델과 실제 스키마의 일치
- 인증 및 민감정보 관리
- 테스트 데이터와 조회 시나리오 검증
- 설계 의도를 설명하는 문서화
